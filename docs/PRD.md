# PRD — 느린 기차

> 제품 기획서 (Product Requirements Document)
> 상태: **싱글플레이 베타** · 최종 갱신: 2026-11-17

---

## 1. 한 줄 소개

옛 **무궁화호**의 느긋한 감성을 담은, 힐링형 **3D 미니어처 기차 웹게임**.
천천히 달리는 객차에 올라 창밖 풍경을 보고, 승객과 인사하고, 간식을 사 먹으며 시간을 보낸다.

## 2. 기획 의도 / 목적

| 구분 | 내용 |
| --- | --- |
| 문제의식 | 경쟁·성과 중심의 게임/서비스가 많아, "아무것도 안 해도 되는" 쉼의 경험이 드물다 |
| 목표 | 설치 없이 브라우저에서 바로 즐기는 **느리고 편안한 경험** 제공 |
| 핵심 가치 | 힐링 · 향수(무궁화호) · 가벼운 사회적 존재감(다른 승객) |
| 장기 방향 | 실제 이용자가 함께 타는 **메타버스형 기차**로 확장 (현재는 NPC로 대체) |
| 개인 목표 | 상용화 가능한 서비스 수준으로 보안·최적화·접근성을 갖춘 개인 프로젝트 |

## 3. 타깃 사용자

- 짧은 시간에 가볍게 쉬고 싶은 사용자 (PC/모바일 모두)
- 레트로·기차 감성을 좋아하는 사용자
- 한국어 사용자 (현재 UI는 한국어 전용)

## 4. 핵심 원칙

1. **정직한 표시** — 구현되지 않은 기능을 완성된 것처럼 보이지 않는다.
2. **NPC 구분** — 베타 승객은 이름표에 "베타"를 붙여 실제 이용자와 구분한다.
3. **결제 없음** — 승차권·간식 구매는 모두 가상이며 실제 결제는 일절 없다.
4. **외부 에셋 없음** — 모든 3D 모델은 코드로 만든 도형 (라이선스 이슈 최소화).
5. **모바일 우선 확인** — 가로(PC)/세로(모바일) 모두 자연스러워야 한다.

## 5. 사용자 경험 (UX 흐름)

```
시작 화면(승차권 모양)
  └ 닉네임 입력 → [승차권 사고 탑승] / [무임승차로 탑승]
        ↓
객차 탑승 (컷어웨이 3D, 천천히 흐르는 창밖 풍경, 임시 기차 소리)
  ├ 이동 · 착석 · 말풍선
  ├ 간식 판매원 → 가까이 가서 [말걸기] → 가상 구매 → 손에 듦
  ├ 승무원 검표 → 표 보여주기 ✔ / 표 없음 → 5초 후 강제 퇴장
  └ 의자 틈 발견 → 숨기 (승무원 검표 회피)
```

## 6. 기능 요구사항

### 6.1 구현 완료 (베타)

| ID | 기능 | 설명 |
| --- | --- | --- |
| F-01 | 객차 3D | 컷어웨이, 양쪽 창문 8개씩, 햇살 그림자, 일반 2인석 24석 + 4인석 테이블 8석 = 32석 |
| F-02 | 시점 | 드래그 회전, 휠/핀치 확대·축소, 가로/세로 반응형 자동 시점 |
| F-03 | 창밖 풍경 | 산·언덕·논밭·나무·집이 시차를 두고 양쪽에서 반복 스크롤 |
| F-04 | 플레이어 | WASD/방향키(카메라 기준), 바닥 터치 이동, 좌석 클릭 착석, 일어나기, 통로 충돌 제한 |
| F-05 | 베타 승객 NPC | 5명. 앉기/일어나기/걷기/말풍선, 겹침 방지, 같은 좌석 중복 착석 방지 |
| F-06 | 간식 판매원 | 일정 간격 등장·중간 정차·"필요한 거 있으신가요?", [말걸기]로 메뉴(5종, 가상 구매), 손에 듦(40초), 버리기 |
| F-07 | 말풍선 | 미리 정해진 문구 7개 선택 |
| F-08 | 입장 방식 | 승차권 구매 / 무임승차 선택 |
| F-09 | 승무원 검표 | 같은 라인에서 만나면 팝업, 표 보여주기 / 표 없음 → 5초 카운트다운 → 강제 퇴장 및 종료 화면 |
| F-10 | 숨는 곳 | 의자 등받이 사이 틈 2곳(투명 터치 영역), 웅크려 숨기, [나가기] |
| F-11 | 사운드 | 코드로 만든 임시 기차 소리, 음소거/볼륨 슬라이더, 설정 유지 |
| F-12 | 저장 | 닉네임·좌석·위치를 localStorage에 저장/복원 |

### 6.2 개발 예정

| 우선순위 | 항목 | 비고 |
| --- | --- | --- |
| 높음 | Supabase 연결 | `Repo`만 교체 + NPC → 실제 접속자 동기화 |
| 높음 | 접근성 개선 | 팝업 `role="dialog"`/`aria-modal`/포커스 관리, 토스트 `aria-live` |
| 높음 | 보안 점검 | CDN 스크립트 SRI, 입력값 검증, 인증/권한(서버 연동 시) |
| 중간 | 기차 소리 교체 | 무료 라이선스 음원 + 출처·라이선스 표기 |
| 중간 | 모바일 조이스틱 | 터치 이동 보조 |
| 낮음 | 승차권 정보 확장 | 좌석·구간 등 |
| 확인 필요 | 숨기 규칙 | "숨으면 검표 회피"는 **임의 규칙** — 유지 여부 결정 필요 |

## 7. 비기능 요구사항

| 항목 | 기준 |
| --- | --- |
| 성능 | 모바일에서도 부드럽게. 픽셀 비율 최대 2, 말풍선·텍스처 사용 후 `dispose` |
| 보안 | 외부 입력은 신뢰하지 않는다. 서버 연동 시 인증·권한·입력 검증 필수 |
| 접근성 | 키보드 조작, 포커스 표시(`:focus-visible`), 다크모드 대응. 팝업 접근성은 개선 예정 |
| 호환성 | 최신 크롬/사파리/엣지, iOS·Android 브라우저, WebGL 필요 |
| 유지보수 | 모든 함수/블록에 한글 주석, 기능별 파일 분리 |

## 8. 개발 범위

**범위 안 (In scope)**
- 싱글플레이 베타, 단일 객차, 가상 구매, 로컬 저장

**범위 밖 (Out of scope, 현재)**
- 실제 결제, 실시간 멀티플레이, 계정/로그인, 다국어, 여러 객차/역 시스템

## 9. 기술 제약

- 빌드 도구 없는 순수 HTML/CSS/JS, `file://`로도 실행 가능해야 함 (ES 모듈 미사용)
- Three.js r128(cdnjs) + OrbitControls(jsdelivr 0.128.0)
- 저장소는 어댑터(`Repo`)로 분리해 Supabase로 교체 가능하게 유지

## 10. 성공 지표 (안)

- 첫 진입 후 이탈 없이 1분 이상 머무는 비율
- 모바일/PC 모두 치명적 오류 없이 5분 연속 플레이
- 간식 구매·말풍선 사용 등 상호작용 발생률

## 11. 리스크 / 열린 질문

- NPC 대신 실제 접속자가 들어오면 동기화·부하·악성 사용자 대응이 필요하다.
- 무임승차 "강제 퇴장" 연출이 사용자에게 불쾌감을 줄 수 있는지 검증이 필요하다.
- 합성 기차 소리의 품질 — 실제 음원으로 교체 시 라이선스 확인이 필요하다.
